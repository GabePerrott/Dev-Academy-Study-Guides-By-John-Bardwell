Unit 4 · Filesystem & Express Router

Data that survives a restart

Everything in a running program lives in memory — and vanishes the moment it stops. To keep data, you write it to a file on disk. Node's filesystem module is how your server reads and writes those files.

Then, so your growing server doesn't turn into one enormous file, Express Router lets you split routes into tidy modules. Both are in this guide, straight from the lecture.

read file → JSON.parse → use it → JSON.stringify → write file
01

Memory vs storage

Two places data can live. The difference that matters most: one is temporary, one persists.

Memory (RAM)

variables, state — while the program runs
  • Fast to read and change
  • Relatively small & expensive
  • Temporary — gone when the app closes or loses power

Storage (disk)

files & folders — on the hard drive
  • Slower to read and change
  • Large & cheap, scales well
  • Persistent — survives restarts

Up to now your data lived in memory — component state, variables. That's perfect while the app runs, but close it and everything's gone. When you need data to stick around, it has to go to storage: a file on disk.

▲ Files aren't the long-term answer for web apps

Reading and writing files is a great way to understand persistent, asynchronous storage — but it doesn't scale, has no enforced structure, and is slow. It's a stepping stone. Real apps use databases, which come later in the course. For now, files are how we practise the ideas.

02

The fs module

Node's built-in filesystem library. Two functions do almost everything: readFile and writeFile.

Code anatomy — reading a file
import * as fs from 'node:fs/promises' const contents = await fs.readFile(filePath, 'utf-8')
Hover or tap a token · import fs/promises · await readFile · pass a path + 'utf-8'
—
Each part explains its job.

Writing is the mirror image. writeFile returns nothing, and it either creates the file or overwrites it if it already exists:

write.ts
await fs.writeFile(filePath, data)  // creates or OVERWRITES the file
◆ These run asynchronously — order isn't top-to-bottom

Because disk access is slow and async, a console.log written after a readFile often prints first — the read is still in flight. If that surprises you, it's the exact lesson from Async & Promises. Both then/catch and try/catch work; try/catch with await gives you cleaner control over ordering.

03

JSON round-trip

A file is text. Your code wants an object. Two functions convert between them — one each way.

When you read a .json file you get a string. To work with it — access keys, update values — you turn it into a JavaScript object. When you're done, you turn it back into a string to write. That's the round-trip:

Code anatomy — parse in, stringify out
JSON.parse(contents) // → usable object JSON.stringify(data, null, 2)
Hover or tap a token · parse: string → object (reading) · stringify: object → string (writing)
—
Each part explains its job.
✖ Forget to parse and you're working with a string

Skip JSON.parse and data is just text — data.find(...) won't work, data[0] gives you a character, not an object. Same at the other end: write a raw object without JSON.stringify and you'll save [object Object]. Parse in, stringify out — every time.

05

Files in a route

Put it together: a GET route that reads and returns data, and a POST route that adds to it and writes back.

A GET route reads the file, parses it, and sends the data as JSON:

get-sticks.ts
server.get('/', async (req, res) => {
  try {
    const json = await fs.readFile(filePath, 'utf-8')
    const data = JSON.parse(json)
    res.json(data)
  } catch (err) {
    res.sendStatus(500)   // internal server error
  }
})

A GET-by-id route reads the param, converts it to a number, and finds the match. A POST route reads the file, appends the new item from req.body, stringifies, and writes it back:

add-stick.ts
server.post('/', async (req, res) => {
  try {
    const newStick = req.body
    const json = await fs.readFile(filePath, 'utf-8')
    const data = JSON.parse(json)
    const newData = [...data, newStick]        // keep the old, add the new
    const newJson = JSON.stringify(newData, null, 2)
    await fs.writeFile(filePath, newJson)
    res.sendStatus(201)
  } catch (err) {
    res.sendStatus(500)
  }
})
▲ Read → modify → write the WHOLE thing

To add one item you don't just write the new item — that would wipe the file. You read the current array, spread it into a new array with the addition ([...data, newStick]), then write the whole thing back. And wrap it all in try/catch with res.sendStatus(500) so a failed read or write doesn't crash the route.

06

Express Router

As routes pile up, move each group into its own file. express.Router() is how.

Doing everything in server.ts gets messy fast. Express Router lets you group related routes — all your stick-insect routes — in their own file, then mount them under a prefix. Inside the router, you write router.get instead of server.get:

Code anatomy — a router module
const router = express.Router() router.get('/', ...) router.get('/:id', ...) export default router
Hover or tap a token · create a router · define routes on it · export it
—
Each part explains its job.

Then in server.ts you mount it under a prefix — and the file stays clean, just wiring prefixes to route modules:

server.ts
import stickRoutes from './routes/sticks.ts'
server.use('/api/v1/sticks', stickRoutes)   // prefix applied ONCE, here
// router's '/'   → /api/v1/sticks
// router's '/:id' → /api/v1/sticks/:id
◆ The prefix is set once, at mount

The key idea (also in the Express Server guide): inside the router file you write '/' and '/:id', not '/sticks'. The /api/v1/sticks prefix is applied a single time by server.use(...). Repeat it inside the router and your real path doubles up. Add cats, otters, dogs the same way — one clean line each in server.ts.

★

Recap

Filesystem

  • Memory is fast but temporary; storage (disk) is slower but persists across restarts.
  • fs/promises: readFile(path, 'utf-8') and writeFile(path, data) — both async, so await them.
  • writeFile creates or overwrites; it returns nothing.
  • Files are a stepping stone — databases come later for real persistence.

JSON & routes

  • JSON.parse string → object (reading); JSON.stringify(data, null, 2) object → pretty string (writing).
  • To add an item: read, [...data, newItem], stringify, write the whole thing back.
  • req.params ids are strings — convert with Number(id) before matching numeric ids.
  • Wrap file work in try/catch with res.sendStatus(500).

Express Router

  • express.Router() groups routes into a module; use router.get/post, then export default router.
  • Mount with server.use('/prefix', router) — the prefix is applied once, so don't repeat it inside.
