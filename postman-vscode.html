Tooling · Postman VS Code extension

Poke the API before you code it

Before you write a single fetch or useQuery, you want to know what the API actually returns — the status, the exact JSON shape, the fields. Postman lets you send that request by hand, right inside VS Code, and read the response. No code, no guessing.

This guide is the fast path: install it, send your first request, and learn the few features that matter for your workflow — then turn a working request straight into fetch code.

method + URL → Send → read the response then write the fetch you already know works.
01

Why use it

It closes the guesswork gap. You see the real response before committing it to code.

When you consume an API in code, there's a frustrating loop: write the fetch, run the app, console.log the result, realise the field is results not data, tweak, re-run. Postman collapses that loop. You send the request manually, see the exact response — status code, headers, and the full JSON — and only then write code against a shape you've confirmed.

It's the natural companion to what you already know from the Consuming APIs guide. Same methods, same status codes, same JSON — but as a tool you drive by hand instead of code you write blind. And because it lives in VS Code, you never leave your editor.

◆ Insight — Postman is the scout, your code is the army

Think of Postman as sending a scout ahead. Before you build the fetchPokemonByName function and wire it into a component, you fire one manual request at pokeapi.co/api/v2/pokemon/pikachu and see what comes back: is it a 200? Is the name under name? Are the types nested in an array? Five seconds of scouting saves twenty minutes of console.log debugging once it's buried in React.

02

Install & sign in

One extension from the marketplace, one free account. A couple of minutes, once.

getting set up
Open the Extensions panel in VS Code (the squares icon, or Cmd/Ctrl+Shift+X).
Search "Postman" and install the official one — publisher Postman, id Postman.postman-for-vscode.
Click the new Postman icon in the activity bar on the left.
Sign in to a Postman account — it's free, and the extension requires it. Create one if you don't have it.
Pick a workspace from the dropdown. That's where your requests and history live.
▲ The sign-in is not optional

Unlike some lightweight API clients, the Postman VS Code extension requires you to sign in to a Postman account — your requests sync to your workspace so they show up in both the extension and the Postman app. The account is free for what you need. If a mandatory login is a dealbreaker for you, there are no-login alternatives (Thunder Client, others) — but Postman is what Dev Academy uses, so it's worth the two-minute setup.

Anatomy of a request

Four parts you set, one button you press. The same pieces you send from code — just laid out as a form.

A request in Postman has the same anatomy as one you'd write in fetch. You pick a method, type a URL, optionally add params / headers / a body, and hit Send:

Code anatomy — the parts of a request
GET https://pokeapi.co/api/v2/pokemon/pikachu ?limit=20&offset=0 Headers: Accept: application/json Body: (none for GET — used with POST/PUT)

The four methods you'll use, same as always:

MethodDoesNeeds a body?
GETRead / fetch dataNo
POSTCreate new dataYes — the thing to create
PUTUpdate existing dataYes — the new values
DELETERemove dataUsually no

To create one: pick your workspace, click the New dropdown in the sidebar, choose HTTP, fill in the details, and Send. (There's also a Postman: Create a new HTTP Request command in the Command Palette.)

05

Collections

Saved, organised requests. Stop retyping URLs — build up a little library of the endpoints you use.

A collection is a saved folder of requests. Instead of retyping pokeapi.co/api/v2/pokemon/... every time, you save each request once and click to re-run it. For a project, you might have a "PokeAPI" collection holding "get pokemon", "get generation", "list types" — each ready to fire.

◆ Insight — collections are your project's API map

As you scout the endpoints your app will use, saving them into a collection builds a living map of your backend. Later, when you're writing the fetch functions, every request you need is sitting there — tested, with a known response. It's also how teammates share endpoints: a collection can be shared so everyone hits the same requests. Requests you send also land in History, so even unsaved ones are recoverable.

06

Environments & variables

Store the base URL once, reference it everywhere with {{curly braces}}. Change it in one place.

Typing https://pokeapi.co/api/v2 at the front of every request gets old — and when you switch from a live API to a local one (localhost:3000), you'd have to edit every request. Variables fix that. You store the base URL as a variable and reference it with double curly braces:

Code anatomy — a variable in a URL
{{baseUrl}}/pokemon/pikachu
Hover or tap a highlighted token above · define once · reference with {{ }} · change in one place
—
Every part explains its own job.

An environment is a named set of these variables — so you can have a "Production" environment where baseUrl points to the live API and a "Local" one pointing at localhost, and switch between them from a dropdown without touching a single request.

▲ Current value vs initial value — and secrets

Each variable has an initial value (synced to the cloud, shared with your team) and a current value (local to you, never synced). Put shared, safe defaults in the initial value; keep anything private — API keys, tokens — in the current value only, or mark the variable as a secret so it's masked. Don't paste an API key into an initial value and sync it to a shared workspace.

07

From Postman to code

The payoff feature — turn a working request into a code snippet, then into your real fetch function.

Here's where scouting pays off directly. Once a request works in Postman, click Code (just below Send) and pick a language — Node.js, JavaScript fetch, cURL, and more. Postman writes out the request as code you can read and adapt:

generated snippet — then your version
// Postman can generate something like this from your request:
const res = await fetch('https://pokeapi.co/api/v2/pokemon/pikachu')
const data = await res.json()

// ...which you then shape into YOUR fetch function —
// the same superagent/fetch style from your workshop.
✖ Generated code is a starting point, not the final answer

Don't paste the snippet in wholesale. It's a reference that confirms the URL, method, and headers are right — but your app has its own patterns (your API-client functions, your error handling, your useQuery wrapping). Read the snippet to check you've got the request correct, then write it your way. The value is the confirmation, not the copy-paste.

That's the whole loop this tool exists for, and how it plugs into everything else you've built:

the scout-then-build loop
Scout in Postman — send the request, confirm status + JSON shape.
Write your fetch / API-client function against the shape you saw (Consuming APIs).
Wire it into a component with useQuery (React Query).
Debug — if the data looks wrong, go back to Postman to check whether it's your code or the API.
Checkpoint: your React app shows undefined, but the same request in Postman returns correct data. Where's the bug?
★

Recap

What & why

  • Postman is an API client — send requests by hand and read the exact response, inside VS Code.
  • Use it to scout an endpoint (status + JSON shape) before writing any fetch code.
  • Install Postman.postman-for-vscode from the marketplace; sign in (free, required).

Sending requests

  • A request = method + URL (+ optional params, headers, body). New → HTTP → fill in → Send.
  • Methods: GET read · POST create · PUT update · DELETE remove. POST/PUT carry a body.
  • Read the response: status code, time, and the JSON body — that shape is what you code against.

Organising & bridging to code

  • Collections save & group requests; History keeps what you've sent.
  • Variables with {{baseUrl}} store repeated values; environments switch sets (live vs local).
  • Keep secrets in the current value or mark as secret — never sync API keys to a shared initial value.
  • Code button generates a snippet — use it to confirm the request, then write it your own way.
