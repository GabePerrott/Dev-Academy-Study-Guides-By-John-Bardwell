The page is a thing you can grab

Before React, making a page interactive meant reaching into it by hand: find the element, change its text, listen for the click. That's the DOM — and understanding it is what makes React click, because React is a machine built to do all this reaching-in for you.

This is the model underneath everything visual. Even when you never touch it directly, it's what your components ultimately drive.

select → change → listen — the whole loop of hand-made interactivity.
01

The page is a tree

HTML you write is static text. The browser turns it into a living tree of objects — that tree is the DOM.

When the browser loads your HTML, it doesn't keep it as text. It builds a tree of objects — one for every tag — nested exactly like your HTML. A <body> holds a <div> holds an <h1>. This live tree is the DOM (Document Object Model), and JavaScript can reach into it and change any node — which instantly changes what you see.

◆ Analogy — the set, not the script

Your HTML file is the script — written once, fixed. The DOM is the set the crew built from it: physical, on stage, and rearrangeable mid-show. When JS moves a prop or changes a line on set, the audience sees it change live — without anyone rewriting the script. JavaScript is the stagehand working the live set, not the author editing the page.

02

Selecting elements

Before you can change something, you have to point at it. That's what a query selector does.

Code anatomy — grabbing an element
const heading = document.querySelector('#title')

The selector string is just CSS: '#id', '.class', or a tag like 'button'. If nothing matches, you get null — so a selection that "does nothing" is usually a selector pointing at the wrong thing.

Changing them

Once you hold an element, you set its properties — and the screen updates the instant you do.

A grabbed element has properties you can read and write. Set .textContent and the visible text changes; toggle .classList and its styling changes. Try it — each button runs one real DOM operation on the little card and shows you the exact line:

04

Events

Interactivity is: when THIS happens, run THAT function. That wiring is an event listener.

A page reacts to the user through events — a click, a keypress, a form submit. You wire a function to an event with addEventListener, and the browser calls your function every time it happens:

Code anatomy — listening for a click
button.addEventListener('click', (event) => { handleClick() })

05

Why React exists

The manual loop works — until the page gets big. React is the machine that runs the loop for you.

Everything so far works. But imagine a page with a list of 50 items, each with a like button, a count, and a highlight. Doing it by hand means dozens of querySelectors and listeners, and remembering to re-run the right updates whenever your data changes. Miss one and the screen shows stale information.

◆ The shift React makes

React flips it around. Instead of you grabbing elements and setting properties step by step, you describe what the page should look like for a given state — and React does the DOM grabbing and updating for you. Change the state, and React works out exactly which nodes to touch. The select–change–listen loop from this guide is still happening; React is just the tireless stagehand running it, so you never write document.querySelector in a component.

the same idea, two eras
// DOM by hand: grab, then set, every time
const el = document.querySelector('#count')
el.textContent = count

// React: describe it, and let React update the DOM
<span>{count}</span>

That's the bridge into Unit 2: React isn't a different universe — it's an automation layer over exactly the DOM you just met.

★

Recap

The model

  • The DOM is the browser's live tree of objects, built from your HTML.
  • Select with document.querySelector('css-selector') — returns the element or null.
  • Change by setting properties: .textContent, .classList, .style.
  • Listen with addEventListener('click', fn) — runs your function each time it fires.
  • The loop select → change → listen is all of hand-written interactivity.

The bridge to React

  • Doing this by hand doesn't scale — easy to miss an update and show stale data.
  • React automates the loop: you describe the page for a state, React updates the DOM.
